# TCP transport validation — 2026-10-16

Issue: [#4](https://github.com/mohripan/capsulet-mesh-train/issues/4). Commands and tool versions: [DEVELOPMENT.md](../DEVELOPMENT.md). Contract: [TCP_PROTOCOL.md](../TCP_PROTOCOL.md).

## Actual process behavior

The native process executable spawns fresh workers with `posix_spawn`, uses kernel-assigned root ports, and kills/reaps remaining children on harness failure. Each normal group has an 8-second overall harness bound; CTest bounds the whole executable at 60 seconds. The test sizes and startup timeouts are fixtures, not performance benchmarks.

The GCC Debug run passed 29 subprocess scenarios: echo with 1, 2, 3, 4, and 5 ranks; late root; fragmented HELLO/data; invalid magic/version/length/representation/rank; truncated HELLO; run/context/world/limit mismatches; invalid READY; missing/stalled/slow-drip startup; peer closure; read/write timeout; concurrent close and call rejection; EINTR; repeated reconnect; duplicate ranks; and incomplete membership. A joined worker in an incomplete group fails without receiving READY.

Representative actual GCC startup timing output with a configured 500 ms total deadline:

```text
startup case=missing elapsed_ms=500
startup case=stall elapsed_ms=501
startup case=drip elapsed_ms=500
startup case=duplicate elapsed_ms=1
startup case=incomplete elapsed_ms=501
```

Slow-drip progress did not renew the deadline. The controlled startup scenarios require failure within 1,500 ms. Read and blocked-write tests use a 250 ms deadline; after failure the transport rejects reuse. The close test requires a blocked read to exit within 1 second of close. Twenty successful construction/exchange/close cycles preserve each worker's `/proc/self/fd` count; twenty failed startup attempts successfully rebind the same port. Closed-peer writes throw with the default SIGPIPE disposition intact.

The resolver test holds a real adapter call beyond a 50 ms deadline using executable-local linker wrappers. It then releases the held DNS call and verifies that input storage survived timeout and the eventual `addrinfo` result was freed exactly once. Ordinary process and container tests resolve real hostnames through the OS.

The pinned Python 3.12.15 image also passed wheel build, isolated import, native-result, and native-exception checks.

Clang AddressSanitizer/UBSan passed the four native/wire/process/resolver entries without reports; the installed consumer was validated in ordinary builds. The TCP-disabled Release build passed all three portable/package tests.

## Remaining evidence

This increment establishes Linux TCP byte transport and startup. All-reduce, tensor lifetime/GIL checks, deterministic training parity, and the four-container trainer belong to #5–#8. The result does not establish native Windows, physical multi-host, CUDA, or distinct-GPU behavior. A timed-out hostname lookup retains its worker until libc returns, as documented in the lifetime contract.
